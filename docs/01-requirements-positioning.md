# 基于大模型的文档智能写作助手：需求与差异化定位

## 1. 项目定位

本项目拟实现一个面向文档与作文生成场景的智能写作助手。系统以大语言模型为核心能力来源，围绕用户输入的写作主题、文体要求、字数范围、表达风格和修改意见，完成从写作意图理解、文章结构规划、正文生成到润色优化和文档输出的完整流程。

项目内核参考 OpenClaw 的智能体运行思想，但不建设通用型、多渠道、强自动化的智能体平台，而是将其思想收缩并改造为面向文档写作任务的轻量化写作内核。系统重点不是“让智能体执行各种外部任务”，而是“让写作任务在多个专业写作步骤中稳定推进”。

因此，本系统的核心定位可以概括为：

> 面向文档写作场景的轻量化大模型写作任务内核与应用系统。

## 2. 建设目标

系统建设目标包括以下几个方面：

1. 降低用户完成作文、报告、说明文、应用文等文本材料的写作成本。
2. 将一次模糊的写作请求拆解为可控的写作流程，包括需求解析、提纲规划、正文生成和润色修改。
3. 提供可复用的写作技能，例如标题生成、提纲生成、扩写、缩写、改写、润色和摘要生成。
4. 支持基本文档输出能力，使生成内容能够以较规范的文档形式保存。
5. 在系统设计上体现对 OpenClaw 智能体内核思想的借鉴，同时通过场景专用化、流程简化和模块重命名形成明显差异。

## 3. 用户对象

系统主要面向以下用户：

1. 学生用户：用于作文、课程论文、读书报告、总结材料等写作辅助。
2. 办公用户：用于通知、总结、方案、汇报材料和普通公文草稿生成。
3. 教学或训练场景用户：用于辅助生成写作样例、提纲和修改建议。

本系统强调“辅助写作”，不将其定义为完全替代人工创作的系统。用户仍然需要对最终内容进行审核、修改和确认。

## 4. 核心需求范围

一期版本建议聚焦以下核心功能：

1. 写作需求输入
   - 输入题目或主题。
   - 选择或填写文体类型。
   - 设置目标字数。
   - 设置写作风格或表达要求。

2. 写作任务解析
   - 提取主题、对象、文体、篇幅和语气要求。
   - 将用户输入整理为结构化写作任务。

3. 提纲生成
   - 根据主题和文体生成文章标题、中心思想和段落结构。
   - 支持重新生成提纲。

4. 正文生成
   - 根据提纲分段生成正文。
   - 保证段落之间具有基本连贯性。
   - 支持议论文、说明文、记叙文和应用文等常见类型。

5. 文本优化
   - 对生成文本进行润色。
   - 支持扩写、缩写、改写和语病修正。
   - 支持根据用户意见进行二次修改。

6. 文档输出
   - 支持保存生成结果。
   - 后续可扩展为 Word 文档导出。

## 5. 功能缩减边界

为了保证项目实现难度可控，本系统不实现 OpenClaw 中的完整通用智能体能力。一期版本建议明确排除以下能力：

1. 不做多通信渠道接入，例如微信、Slack、Telegram、Discord 等。
2. 不做复杂长期自主代理，不让系统在无人监督下持续执行任务。
3. 不做大规模插件市场，只保留少量写作技能。
4. 不开放高风险外部工具执行能力，例如任意命令行、浏览器自动操作和系统文件操作。
5. 不追求复杂长期记忆，只保留当前写作任务上下文。
6. 不实现多智能体协作，只采用单任务内核加多个写作技能的方式。

这些缩减能够让系统更贴合“文档智能写作助手”的主题，也更适合作为课程设计、毕业设计或论文实现项目。

## 6. 与 OpenClaw 的关系

OpenClaw 的典型特点是通用智能体运行框架，通常包含模型接入、任务调度、工具调用、记忆管理、技能扩展和多渠道交互等能力。它的重点是让大模型能够连接外部工具和消息通道，完成更广泛的自动化任务。

本项目只借鉴其内核思想，不复制其完整形态。

可借鉴部分包括：

1. 模型适配思想：将大模型调用封装为统一接口。
2. 任务运行思想：把用户请求转化为可执行任务。
3. 上下文管理思想：在一次任务过程中保存输入、提纲、正文和修改意见。
4. 技能模块思想：将提纲、正文、润色、摘要等能力封装为独立技能。
5. 流程编排思想：按照写作流程调用不同技能并整合结果。

需要形成差异的部分包括：

1. 应用领域不同：OpenClaw 面向通用智能体，本系统面向文档写作。
2. 内核目标不同：OpenClaw 强调自动化执行，本系统强调写作流程控制。
3. 工具范围不同：OpenClaw 可连接多类工具，本系统只保留写作相关能力。
4. 记忆机制不同：OpenClaw 可支持长期记忆，本系统主要保存当前文档上下文。
5. 技能体系不同：OpenClaw 技能泛化，本系统技能围绕文档生成和文本优化设计。
6. 风险控制不同：本系统减少外部执行能力，降低安全风险和实现复杂度。

## 7. 差异化内核命名建议

为了避免与 OpenClaw 过于相似，建议将系统内核命名为“写作任务内核”或“文档生成内核”，并采用具有写作场景特征的模块名称。

建议模块命名如下：

| 模块名称 | 职责 |
| --- | --- |
| WritingTaskEngine | 写作任务总控，负责推进一次写作流程 |
| RequirementParser | 解析用户写作需求 |
| OutlinePlanner | 生成文章结构和写作提纲 |
| DraftComposer | 根据提纲生成正文草稿 |
| RevisionProcessor | 根据用户意见进行润色、改写和修订 |
| ContextBinder | 管理当前写作任务上下文 |
| SkillRegistry | 管理写作技能 |
| ModelAdapter | 统一封装大模型调用 |
| DocumentExporter | 输出文本或文档文件 |

这些名称能够体现系统是文档写作专用内核，而不是通用智能体平台。

## 8. 一期最小可用版本

一期最小可用版本应完成以下闭环：

1. 用户输入写作主题、文体、字数和风格。
2. 系统解析写作需求。
3. 系统生成提纲。
4. 系统根据提纲生成正文。
5. 用户可以对正文进行润色或改写。
6. 系统保存最终文本结果。

这一闭环完成后，项目已经具备可演示性。后续再扩展 Word 导出、模板库、历史记录、更多文体和更精细的风格控制。

## 9. 后续阶段安排

完成本阶段后，后续建议按以下顺序推进：

1. 第二阶段：设计系统总体架构和核心流程图。
2. 第三阶段：设计轻量化写作任务内核。
3. 第四阶段：实现核心后端功能。
4. 第五阶段：实现前端写作工作台。
5. 第六阶段：实现文档输出和测试材料。
6. 第七阶段：整理论文说明、截图和项目总结。

## 10. 阶段结论

本项目应以“文档写作任务”为中心，而不是以“通用智能体自动化”为中心。OpenClaw 可作为内核设计思路来源，但最终系统需要在应用场景、模块职责、功能范围和技术实现上保持明显差异。通过缩减通用能力、强化写作流程和文档生成能力，可以形成一个实现难度适中、主题聚焦明确、便于论文阐述和系统演示的项目方案。
